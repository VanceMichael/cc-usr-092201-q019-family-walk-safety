# 亲子健走安全联络

记录亲子健走中的监护、检查点和安全联络资料。

## 资料范围

领域资料位于 `fixtures/domain.json`，结构约定见 `contracts/domain.schema.json`。当前记录类型包括参赛家庭、监护授权、出发批次、检查点记录、安全事件、交接确认，状态示例为待核验 → 已出发 → 行进中 → 需协助 → 已交接 → 已闭赛。这些样例使用虚构标识，不含真实个人资料、账号或连接凭据。

已整理的业务事实：

- 赛事有两千组亲子家庭参加
- 家庭按多个组别分批出发
- 路线长且经过多个城市地标

## 安全联络后台

`safety_ops` 包在公开资料约定之上提供赛事后台核心能力：

- `models.py`：家庭、成员、监护授权、紧急联系人、出发批次、检查点、检查点记录、安全事件、交接确认与家长通知，流程状态沿用领域资料约定。
- `service.py`（`RaceService`）：
  - 出发前核验家庭成员、监护授权、健康提示、批次与紧急联系人，核验通过才允许出发；
  - 检查点记录支持离线登记，联网后按 `record_id` 幂等去重、按现场真实时间合并，计程取检查点里程，重复或乱序上传不会重复计程；
  - 到达、退出、临时转组、医疗观察、终点核销五类记录驱动家庭状态推导；
  - 路线封闭、儿童走散、备用监护人接回、提前结束、终点未核销分别开立事件，结案前必须满足对应处置条件（如儿童走散须先完成与授权监护人的交接）；
  - 交接确认要求交接对象对本家庭每名儿童都持有有效监护授权，完成后向家长发送明确联络结果；
  - 指挥席按组查看每家庭最后确认点、组内收尾位置与未解决事件；全部家庭完成安全交接且无未解决事件才允许闭赛，看到完赛数字不算结束。
- `access.py`：位置信息只向指挥席、检查点、医疗等负责岗位及本家庭披露，其他角色不可见。

## 本地校验

项目自带的测试会读取样例并检查领域标识、版本、记录类型、流程状态和事实说明，并覆盖后台的核验、离线合并、事件处置、位置可见性与闭赛闸门。后续服务应继续兼容这份公开资料约定。
