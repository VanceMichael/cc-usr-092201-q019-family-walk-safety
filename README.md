# 亲子健走安全联络

记录亲子健走中的监护、检查点和安全联络资料。

## 资料范围

领域资料位于 `fixtures/domain.json`，结构约定见 `contracts/domain.schema.json`。当前记录类型包括参赛家庭、监护授权、出发批次、检查点记录、安全事件、交接确认，状态示例为待核验 → 已出发 → 行进中 → 需协助 → 已交接 → 已闭赛。这些样例使用虚构标识，不含真实个人资料、账号或连接凭据。

已整理的业务事实：

- 赛事有两千组亲子家庭参加
- 家庭按多个组别分批出发
- 路线长且经过多个城市地标

## 本地校验

项目自带的测试会读取样例并检查领域标识、版本、记录类型、流程状态和事实说明。后续服务应继续兼容这份公开资料约定。

## 安全联络后台

`safety_core` 是赛事安全联络后台的领域核心，覆盖两千组家庭、13.5 公里滨江赛道的完整流程：

- **出发前核验**（`verification.py`）：家庭成员、监护授权、健康提示确认、出发批次、紧急联系人逐项核对，全部通过才允许 `depart` 出发。
- **身份对应**（`RaceControl.lookup`）：凭家庭或成员标识直接查到孩子、监护人、出发组别和最近检查点，工作人员不再靠报名手机号逐级转问。
- **检查点离线登记**（`tracking.py`）：到达、退出、临时转组、医疗观察、终点核销都可在离线设备登记；联网后按 event_id 去重、按真实发生时间合并，里程只计一次。
- **安全事件处置**（`incidents.py` + `control.py`）：路线封闭、儿童走散、备用监护人接回、提前结束、终点未核销分别建单处置；备用监护人必须持有效授权；需要交接的事件销单前必须完成交接确认。
- **位置披露**（`disclosure.py`）：位置只向负责岗位（指挥席、检查点岗位、医疗岗位）及本家庭开放，其他家庭查不到。
- **指挥席视图**（`RaceControl.group_status`）：每组每户的最后确认点与状态，以及仍未解决的事件。
- **家长联络结果**（`notifications.py`）：事件受理与销单都会给家长留一条明确的联络结果，可回查。
- **闭赛把关**（`closure.py`）：全部已出发家庭完成交接确认且无未解决事件才允许闭赛——只看终点完赛数字不够。
